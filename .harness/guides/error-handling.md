# 错误处理指南

## 1. 优先级（时间紧张时）

### P0 — 必须处理（阻塞发布）
- 应用崩溃 / 白屏
- 沙箱执行逃逸风险
- API Key 泄露风险

### P1 — 应该处理（用户体验）
- AI 响应错误提示（网络超时、模型不可用）
- 代码执行失败提示（语法错误、超时）
- 沙箱安全拦截提示（告知用户为何被阻止）

### P2 — 可以延后（不影响核心）
- 复杂的错误恢复逻辑
- 详细的错误日志分级（debug/info/warning/error）
- 优雅的降级体验（如网络断开后离线模式）

## 2. 快速决策

| 场景 | MVP 做法 |
|------|----------|
| 未知异常 | `try/except` + 打印日志 + 返回用户友好提示 |
| AI 接口超时 | 捕获超时，返回 "请求超时，请重试" |
| 沙箱执行失败 | 返回 stderr + 建议（检查语法/循环） |
| 数据库错误 | 记录日志，返回 "操作失败"，不暴露 SQL |

## 3. 日志规范

- 使用 `structlog` 或标准 `logging`
- 格式: `[{timestamp}] [{level}] [{module}] {message}`
- 敏感字段自动过滤: `api_key`, `token`, `password`, `secret`
